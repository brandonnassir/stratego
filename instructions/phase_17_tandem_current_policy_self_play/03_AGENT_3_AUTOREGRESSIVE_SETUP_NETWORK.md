# Phase 17 — Agent 3
## Scaled autoregressive setup policy and robustness gate

## Mission

Build the new setup half of Phase 17: a small paper-shaped causal Transformer that
continuously samples legal, diverse setups from its current raw distribution and
learns from completed-game outcomes plus the paper's entropy/diversity mechanism.

This is the phase's only new model and the only local component authorized for an
extended preflight experiment. You do not integrate the move collector, build the
remote evaluator, or launch the 12-hour run. Read
`00_PHASE_17_SEQUENCE_AND_COMMON_CONTRACT.md` completely and consume a verified Agent
1 handoff.

## 2. Model architecture

Implement exactly:

```text
pre-layernorm decoder-only causal Transformer
4 decoder blocks
d_model = 128
4 attention heads
FF width = 512
sequence length = 41 (start + 40 placements)
```

Use learned piece and position embeddings unless Agent 1 freezes the paper's different
choice. Heads at all 40 prefixes:

- 12-way next-piece logits;
- 3-way W/D/L logits;
- scalar conditional-entropy prediction.

Report the exact trainable parameter count. The expected total is approximately 0.8M;
fail the architecture gate if it falls outside Agent 1's frozen tolerance rather than
quietly changing widths.

The model input is only the canonical prefix, position, and information derivable from
the remaining inventory. No enemy setup, family label, opponent identity, terminal
outcome, future token, or other privileged field enters inference.

Required causality test: changing teacher-forced suffix tokens cannot change any
earlier-prefix output.

## 3. Inventory mask and orientation

Derive remaining counts from the prefix at every position. An exhausted piece receives
negative-infinity/boolean exclusion before normalization and sampling. Fail on an
invalid prefix rather than repairing it.

Generate a canonical own-orientation 40-tuple, validate the exact Stratego inventory,
then call the accepted orientation helper separately for Red and Blue. Test the known
reversed-Blue failure explicitly. Canonical Blue must never be passed directly to the
engine.

No setup library, authored template, Phase 10 selector, or library fallback is allowed
in training. Evaluation may use fixed opponent setups outside this module.

## 4. Reproducible batched generation

Categorically sample each token from the masked distribution using explicit run/game/
side/prefix seed domains. Identical raw snapshot and seeds reproduce the entire setup
and trace; a changed seed permits a different legal sample.

Provide vectorized generation pools under a frozen raw setup snapshot. Benchmark pool
sizes from 512 through 1,000 per side only far enough to choose the smallest size that
keeps the game creator supplied. Refill under the same frozen snapshot if exhausted.
When the setup snapshot changes, do not silently relabel old pool entries as current.

Every sample returns the complete Agent 1 `SetupEpisode` behavior record, including
the snapshot/model-state digest and all prefix behavior data. Training data is always
generated by raw setup weights; EMA generation is an evaluation-only API.

## 5. Outcome binding and loss

On terminal game completion, bind the same result to both recorded side episodes from
their own perspectives. Test Red win, Blue win, and draw signs independently.

Implement the exact setup advantage and coefficients frozen in Agent 1's paper map.
At minimum the learner must contain distinct, logged terms for:

- clipped setup PPO policy loss, epsilon 0.2;
- behavior KL and its setup-only adaptive controller;
- W/D/L value cross-entropy;
- conditional-entropy prediction error;
- the entropy/information contribution to the setup advantage;
- total loss and gradient norm, clipped at 0.5.

Use all 40 prefixes and no top-quartile move-advantage filter. Compute ratios from the
recorded behavior probabilities, never by re-running the latest network as behavior.
Old completed games are therefore valid only with their attached behavior identity.

Run five setup epochs per setup iteration. Shuffle deterministically within each epoch
and record the epoch/minibatch order. Raw weights update first; setup EMA updates only
after the complete setup update.

## 6. Throughput decision — not a recipe experiment

Measure, on the intended training device:

- setup-pool generation time and samples/second;
- one-epoch and five-epoch setup update time at Agent 1's planned batch size;
- memory high-water mark;
- projected fraction of a tandem iteration and 12-hour budget.

Keep five epochs unless the measurement shows it materially compromises the fixed
move cadence or prevents the expected 12-hour iteration count. Do not compare setup
strength at different epoch counts. If five epochs are prohibitive, report the numbers
and request the operator's decision; do not reduce epochs autonomously.

## 7. Extended setup gate

The complete gate should target 60–90 minutes and may sample more when generation is
cheap. It must include at least 5,000 setups divided across Red/Blue orientation.

### Hard correctness

- zero inventory, legality, placement, lake, or orientation failures;
- adversarial logits cannot sample exhausted types;
- causal suffix-mutation test passes;
- deterministic snapshot/seed trace passes;
- every generated board round-trips through game creation;
- no library or repair fallback is reachable.

### Meaningful diversity

Measure before and after the short learning soak:

- exact and reflection-class unique counts;
- empirical per-square and mean prefix entropy;
- sequence information/entropy distribution;
- mean/quantile pairwise Hamming and class distance;
- flag-square and effective flag support;
- bomb-location/pattern support and top-token concentration;
- collision rate and most frequent reflection class.

Raw uniqueness alone is not evidence because mirrored copies can inflate it. Freeze
production warning/hard thresholds from the initial distribution and soak, respecting
the common contract's provisional hard floors.

### Learning and outcome binding

- synthetic Red/Blue/draw sign tests;
- reward-flip test: reverse only outcomes and demonstrate the expected policy-gradient
  direction change;
- short real self-play integration supplied by a minimal current move-policy fixture;
- completed outcomes produce nonzero policy/value/entropy gradients, optimizer steps,
  and a changed raw model-state digest;
- entropy and diversity do not immediately collapse;
- identical data/order/checkpoint state reproduces the update;
- raw, EMA, optimizer, setup KL, RNG, and episode data round-trip.

Do not claim the short soak establishes setup strength. It establishes legality,
diversity, and a working outcome-to-update path.
